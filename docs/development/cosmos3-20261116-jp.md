# Cosmos3 Edge／Nano：CPUによるテキスト・画像・動画推論

2026-11-16。開発対象をCosmos-Reason2-2Bから、NVIDIAのCosmos3 Edge／Nanoに変更した。
公開スナップショットの実重みをAIKernelのCPUエンジンで動かし、公式参照との数値比較を行った。
モデル取得にChromeの認証情報や保存済みHFトークンは使用していない。

## 実装と再現条件

利用方法は [Cosmos3推論](../cosmos3-inference.md)。
推論APIは `Cosmos3Model` と `Cosmos3Variant.Edge / Nano`。
入力はテキスト、RGB画像、元の時刻を持つ動画フレーム。出力はテキストである。
Cosmosの映像・音声・アクション生成器は取り込まない。

- Edge：専用BPE、対話テンプレート、ReLU²、Q/K正規化を使わないGQA、SigLIP2、HWCパッチ、各フレームの視覚処理、projector。
- Nano：Qwen3-VLのNFC BPE、DeepStack、GQA、Q/K正規化、SwiGLU、2フレームをまとめる時間パッチ。
- 共通：3軸MRoPE、KVキャッシュ、greedy生成、入力上限、キャンセルと内部作業配列の消去。
- safetensorsのBF16重みとFP32活性化の積和はFP64で累積し、最後にFP32へ丸める。視覚LayerNormの平均・分散もFP64で集計する。
- モデル全体をFP32へ展開しない。CPUのAVX2を検出してBF16を展開する。非対応CPUにはスカラー経路を用意する。

実測環境の詳細は [environment.json](evidence/cosmos3-20261116/environment.json)。CPUワーカーは4。
公式参照はTransformers `3a134bc37f7c22c801b618e289b0255425f22647`（5.24.0.dev0）とTorch 2.15.0+cpu。
公式側では保存BF16重みをFP32へ読み込み、eager attentionで評価した。
AIKernelの実行時にはPython、Torch、CUDA、外部APIを使っていない。

モデルの固定revision、ソースshardのSHA-256、取り込み先のSHA-256は各
[Edge manifest](evidence/cosmos3-20261116/edge-import.json)／[Nano manifest](evidence/cosmos3-20261116/nano-import.json) に記録した。
各ソースshard全体を配布元のLFSハッシュと照合してから、公式の名称変換で必要なテンソルだけを抽出した。
重みのdtypeとバイト列は変更していない。

## 実重みの数値比較

同じRGBと位置IDを渡し、公式側の自動リサイズ・再サンプリングは無効にした。
画像は96×64の赤色画像。動画は同じ寸法の8フレーム、2fpsで赤3枚→緑3枚→青2枚。
一括prefillの公式参照に対し、AIKernelは逐次forwardで全入力位置のロジットと固定8トークンの生成を比較した。
生成テストではEOS後も数値検証用に8ステップまで続け、通常APIのEOS終了とは区別した。

| モデル | 入力 | ロジットの最大絶対誤差（入力＋8生成ステップ） | 基準1e-3 |
|---|---|---:|---|
| Edge | テキスト | 0.00002861023 | 合格 |
| Edge | 画像 | 0.00022435188 | 合格 |
| Edge | 動画 | 0.0006227493 | 合格 |
| Nano | テキスト | 0.000052914023 | 合格 |
| Nano | 画像 | 0.00007581711 | 合格 |
| Nano | 動画 | 0.00085926056 | 合格 |

全6条件で、生成8トークンのID列が公式参照と一致した。ハッシュを各条件の `*-tokens.json` に記録した。
前処理の画素パッチは誤差0。視覚特徴・DeepStackも1e-3以内。
詳細は [Edge比較](evidence/cosmos3-20261116/edge-real/comparison.json) と
[Nano比較](evidence/cosmos3-20261116/nano-real/comparison.json)。
これは上記入力・環境での検証であり、任意の入力や別ハードウェアでのビット一致を保証するものではない。

小規模の独立した公式モデルでも、2アーキテクチャ×3保存dtype（F32／BF16／F16）×3入力の18条件を検証した。
数値ゲートは1e-5、最大誤差は4.62e-7以下。全条件で8トークンのID列が一致した。
トークナイザーは各8例、テンプレートと位置IDはEdge16例／Nano8例で一致した。
Edgeはthinkingの有効・無効、両モデルは空のsystem、画像、動画、混在入力も確認した。

## 誤差超過をどう扱ったか

Nano動画では、初期のFP32累積で最大0.0025635となり、1e-3基準を超えた。
公式と同じアテンションのスケール乗算、累積の分散、LayerNormの集計改善で0.0010641まで下がったが、これも不合格とした。
FMAの追加やRMSNorm／softmaxの高精度集計は参照誤差が悪化したため採用していない。
最終的にBF16内積をFP64で累積する実装が0.0008593となり、元の基準を通過した。
許容誤差や検証する入力位置を変更して合格にしたものではない。

比較条件の影響も独立に調べた。公式実装だけで一括prefillと逐次forwardを比較すると、動画ロジットの最大差は0.0004406だった。
この差だけではAIKernelの初期超過を説明できなかったため、比較条件を変更するだけの対応は採用していない。
[公式同士の比較](evidence/cosmos3-20261116/official-prefill-modes.json) と
[不採用段階の記録](evidence/cosmos3-20261116/numerical-development.json) を残した。

## 実ファイル入力と回答品質

公開APIからPNG、FFV1動画、テキストを入力し、EOSまで生成した。上限は64トークン。
これは性能ベンチマークではなく、CPU使用率10%以下の待機条件も適用していない。
実行時間を128トークン固定の性能比較や既存ブログのグラフへ流用しない。

| 入力 | Edgeの回答 | Nanoの回答 |
|---|---|---|
| `What is 2 + 2?` | `4` | `4` |
| 赤いPNG画像 | `The image is entirely red.` | `Red` |
| 赤→緑→青の動画 | `red, orange, yellow, green, blue, indigo, purple` | `Red, orange, green, blue.` |

動画の回答には素材にない色が含まれた。公式実装でも同じ生成列となっており、これをAIKernelの数値一致によって解消したとは扱わない。
数値比較の合格と、認識・回答品質の評価は別である。回答とトークン列は [API確認記録](evidence/cosmos3-20261116/api-generation.json) を参照。
この単純な色素材の確認だけで、一般の動画理解や業務精度を確認済みとはしない。

## 回帰と残る範囲

- Coreの回帰テスト909件が合格。既存のGemma／Bonsaiのテストを含む。
- 取り込みツールのハッシュ不一致拒否、メタデータ更新、モデル別の名称変換の3件も合格。
- 新規パッケージ依存は追加していない。準備・公式参照用Pythonコードは製品の推論経路には入らない。
- Cosmos3のGPU推論、AVX-only実機、Serverでの7GB上限制御とSSD退避は今回の検証対象外。
- Nanoの推論重みだけで17,534,247,392 bytesある。Gemmaで検証した7GB枠の結果を、そのままNanoへ適用しない。
- 128トークン固定の低負荷性能測定、長い文脈、実写動画での認識品質評価は別途必要。
